    A CONNECTOR, NOT A BANK

    Put the check in the flow.

    Your application calls PaymentShield. PaymentShield gates provider checkout. The provider confirms the result.

    01

    Run the connector

    Install dependencies and generate the checkout model.

    python -m pip install -r requirements-connector.txt
python scripts/train_checkout.py
python -m uvicorn src.connector.api:app --host 127.0.0.1 --port 8000

    The existing Streamlit application remains available separately.

    02

    Configure provider test mode

    Set server environment variables. Never place the secret in JavaScript.

    PAYMENTSHIELD_PROVIDER=razorpay_test
RAZORPAY_KEY_ID=rzp_test_…
RAZORPAY_KEY_SECRET=…
RAZORPAY_WEBHOOK_SECRET=…
PAYMENTSHIELD_MERCHANT_TOKEN=…

    Restart the service. Live keys are deliberately rejected.

    03

    Use the checkout client

    <script src="/static/connector-sdk.js"></script>
const shield = new PaymentShield();
const order = await shield.createOrder({
  item: 'headphones', quantity: 1,
  idempotency_key: crypto.randomUUID()
});
// Only a cleared order can start checkout.
await shield.checkout(order.id);

    Initial client supports this service’s same-origin store. A cross-site merchant SDK and authenticated customer-history ingestion are future work.

    04

    Confirm, don’t assume

    Set your public HTTPS webhook URL to:

    POST /api/v1/webhooks/razorpay

    Subscribe to payment.captured, payment.authorized, and payment.failed. Raw-body HMAC verification and duplicate suppression run server-side. Only captured payments become paid.

    Explore the API reference ↗
    What this does not do

    It cannot intercept unrelated payments inside a personal Google Pay account. Test mode does not demonstrate a live Google Pay debit. Customer identity, multi-merchant onboarding, production rate limiting, durable hosting, and real-data validation are not complete.
